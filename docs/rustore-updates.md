# Обновления родительского приложения через RuStore

**PARENT-RUSTORE-D-001 — Принято пользователем, 2026-09-29.** Поддержать
обновления отдельного родительского приложения так же, как в детском.
Перенесён его механизм `ru.rustore.sdk:appupdate:10.5.1`:
[официальная документация](https://www.rustore.ru/help/sdk/updates/kotlin-java/10-5-1).

## Поведение

После успешного ввода PIN `ParentsApp` подключает `AppUpdateHost` вне
навигационных экранов. При RESUMED он проверяет доступность новой версии.
Стандартный диалог RuStore предлагает отложенное скачивание (`FLEXIBLE`),
родитель может отказаться или пользоваться приложением во время загрузки.

Перед запуском скачивания заново запрашивается одноразовый `AppUpdateInfo`.
Обычная рекомпозиция, навигация и пересоздание Activity не создают повторное
предложение уже показанного скачивания: ViewModel принадлежит Activity.
После ухода в фон PIN блокируется по прежнему правилу. Вернувшийся пользователь
сначала вводит PIN; проверка обновления возобновляется после разблокировки.
Во время закрытого PIN-gate запросы и слушатель обновлений не активны.

Скачанный пакет отслеживается слушателем SDK и повторной проверкой при возврате,
в том числе в новом процессе. Диалог «Обновление готово» предлагает
«Установить» или «Позже». Установка происходит только по подтверждению через
`completeUpdate(FLEXIBLE)` с перезапуском приложения. «Позже» откладывает
предложение до следующего foreground/возобновления host.

При уходе из RESUMED scope проверки отменяется, слушатель освобождается;
поздний ответ не открывает диалог в фоне. Отсутствующий/неавторизованный RuStore,
сеть и ошибки SDK не блокируют отчёт. Ошибки доступны в logcat с тегом
`RuStoreUpdates`. Ошибка установки позволяет повторить её явно.

## Состав интеграции

- [Каталог версий](../gradle/libs.versions.toml) фиксирует SDK 10.5.1;
  [Maven-репозиторий](../settings.gradle.kts) ограничен `ru.rustore.sdk`.
- `app/updates` содержит платформенный адаптер, контракт, ViewModel и UI host.
- `app/di/AppUpdateModule` создаёт singleton менеджер с Application Context.
- Подключение находится в [ParentsApp](../app/src/main/java/ru/nksk/parentsapp/app/ParentsApp.kt).

SDK работает с пакетом родительского приложения `ru.nksk.parentsapp`.
Детский applicationId не перенесён. PIN, выбранный device ID, родительские
данные, квесты и backend-контракт механизм обновления не изменяет.
Версия приложения и ключ подписи этим изменением не меняются.

## Проверка

Перенесены девять JVM-тестов из детского приложения: отказ от скачивания,
явная установка и откладывание, текущая загрузка, недоступный магазин,
отмена фоновой проверки, ошибка установки и повторы подготовки скачивания.

Команда проверки:

```sh
./gradlew testDebugUnitTest :app:assembleDebug :app:compileReleaseKotlin :app:lintDebug
```

Результат: 88 JVM-тестов, debug APK и компиляция release прошли; lint без
ошибок, 24 предупреждения.

Проверка сборки и JVM-тестов не подтверждает установку настоящего обновления
из RuStore. Приложение, эмулятор и instrumented tests не запускаются.

Для ручной проверки нужны актуальный RuStore с авторизацией и доступная
более новая сборка родительского приложения с тем же applicationId,
совместимой подписью и большим versionCode. SDK не публикует приложение
в консоли RuStore. Проверить отказ от скачивания, загрузку с уходом в фон,
возврат через PIN, «Позже», явную установку и сохранность привязки после
перезапуска. Также проверить обычный вход без RuStore и без доступной версии.
